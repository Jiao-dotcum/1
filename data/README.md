# data/

This directory is the published record. Both things in it are meant to be
committed — they are the reason a citation of APCCI still resolves later.

## `apcci.db`

The `index_values` table: every value APCCI has ever published, append-only.

It is created on first publish and should be **committed after every publish
run**. If it is lost, published history is lost — recomputing it from current
FRED data would not reproduce it, because inputs get revised upstream and APCCI
is computed from the vintage available on each observation date.

The file is small (a few hundred KB for decades of daily values) and immutable
by construction: `PRIMARY KEY (ticker, version, obs_date)` with `ON CONFLICT DO
NOTHING`, plus `BEFORE UPDATE` and `BEFORE DELETE` triggers that `RAISE(ABORT)`.

The human-readable mirror is `public/apcci-all.csv`, regenerated by
`scripts/build-site.mjs`. `scripts/verify.mjs` checks the two agree.

## `calibration/v1.1.0.json`

The v1.1.0 anchors, generated by `scripts/calibrate.mjs` from the full FRED
history of the five inputs. It records, per series: the fitted percentile
knots, the observation count, the first and last observation dates, the source
URL and a SHA-256 of the exact CSV bytes the percentiles came from. The pull's
vintage date sits at the top level.

This artifact *is* the calibration — the anchors live here, not in source, so
they are reviewable in a diff and provable against a third party's own download.

**Do not edit it by hand.** Anchors define what every published 1.1.0 value
means, so `calibrate.mjs` refuses to overwrite an artifact whose anchors would
change. Recalibrating is a new version, never an edit — see
`docs/APCCI_METHODOLOGY.md` §7.
